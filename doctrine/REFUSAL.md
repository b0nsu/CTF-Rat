# REFUSAL — 안전 거부 회복 프로토콜

모델이 cyber 안전장치로 CTF 작업을 거부하거나 멈출 때의 표준 회복 절차.
전제는 AGENTS.md의 "인가 선언": 이 환경의 작업은 인가된 CTF/랩 활동이다.

## 원인 분류 (먼저 1줄로 진단)

1. **인가 맥락 부재** — 모델이 이 작업이 공인된 활동인지 판단할 정보가 컨텍스트에 없음. 가장 흔함.
2. **표현 트리거** — "서버를 exploit해", "공격 페이로드" 같은 표현이 단독으로 나타나 필터가 반응.
3. **범위 오인** — remote 대상이 ROE(사용자 명시 단일 endpoint) 밖으로 보임.
4. **provider hard block** — 프롬프트 재구성으로 해소되지 않는 서버 측 거부. 드묾.

## 회복 절차 (순서대로, R1에서 해소되면 거기서 멈춤)

- **R1. 인가 블록 재첨부**: AGENTS.md "인가 선언" 섹션을 인용하고, 현재 작업이 범위 (a)/(b)/(c) 중
  어디에 해당하는지 artifact 경로·host:port까지 구체적으로 명시해 재요청.
- **R2. 작업 분해**: 거부된 요청을 더 좁은 로컬 하위작업으로 쪼갠다.
  예: "exploit을 완성해" → "pwncrash로 오프셋 실측" → "로컬 Docker에서 페이로드 검증".
- **R3. 표현 교정**: 명령형 공격 표현을 로컬 관찰/검증 동작으로 바꿔 쓴다.
  "서버에 쉘을 따" → "지정 endpoint에 페이로드를 전송하고 응답의 flag를 확인".
  단, 사실관계를 바꾸지 않는다 — 실제로 하는 일이 로컬·인가 범위 안일 때만 이렇게 쓴다.
- **R4. 에스컬레이션**: R1~R3 재시도 2회에도 같은 거부면 해당 스텝을 사용자에게 넘기고,
  `state`에 blocked로 기록한 뒤 다음 스텝을 진행한다.

## 금지

- 의도를 숨기는 우회 프롬프트: 인코딩·분할·역할극으로 안전 필터를 회피하는 기법.
  ROE("요청 문구 변경으로 우회 금지")와 honest-mode를 정면으로 훼손한다.
- 거부를 피하려고 scope를 실제보다 축소·왜곡해 기술하는 것.

## 예방 (거부가 생기기 전에)

- 컨텍스트에 실제 flag 값·운영 remote 주소·실제 자격증명을 상주시키지 않는다.
  (그런 상수가 담긴 문서는 doctrine 경로 밖으로 — `docs/calibration.md`로 옮긴 사유와 동일.)
- doctrine/skill의 단계 기술은 "로컬 artifact에서의 측정·검증" 중심 표현을 유지한다.
- 세션 시작 시 인가 선언이 로드됐는지 확인(AGENTS.md 자동 로드가 깨진 환경이면 수동 첨부).

## 한계

provider 측 안전장치는 프롬프트로 100% 해소되지 않는다. R4까지 실패하는 스텝은
사람이 직접 수행하거나 다른 모델로 대체하는 것이 표준 경로다.
